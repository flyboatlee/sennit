受系统沙箱限制的功能

App Store 版运行在系统沙箱里，下面这几项能力是系统本身不提供的，因此这一版不含它们（不是坏了，也不是省掉了功能）：

功能 App Store 版 沙箱外运行时
SSH / Telnet / SFTP / 端口转发 / 批量执行 / 录制 / AI / 笔记 可用 可用
内嵌浏览器（Web 类型资产） 不含。双击资产会给出提示，资产本身不会被删除 可用
从 ~/.ssh 导入配置、列出本地密钥 不含（沙箱读不到家目录） 可用
SFTP 本地目录 只能访问你在对话框里选择过的文件夹 任意目录
本地终端 不含。App Store 版的系统沙箱不允许应用对伪终端设置行编辑与前台进程组，键会重复、方向键失效 —— 这是系统限制，在沙箱内无法修复 可访问整台机器

两个版本共用同一份保险库格式：在沙箱外运行时建的资产，用 App Store 版打开也能看到（只读不影响， 只是那几项功能用不了）。

常见问题

忘记主密码了，能找回吗？

不能。保险库用 AES-256-GCM 加密，密钥由你的主密码派生，我们不保存主密码，也没有后门或托管密钥。 唯一的办法是用之前导出的备份恢复（备份若设了口令，同样需要那个口令）。

连接时提示「主机密钥未知」或「主机密钥变了」

第一次连接一台机器时，应用会问你能否信任它的主机密钥 —— 核对指纹后确认即可。 如果一台连过的机器突然提示密钥变了，可能是重装了系统，也可能是有人在中间人攻击， 这两件事应用分不出来，所以把决定权交给你：请通过其他渠道核实服务器指纹后再继续。

SFTP 打开本地目录时提示「需要先选择一个文件夹」

App Store 版受系统沙箱限制，只能访问你明确授权过的目录。点提示里的按钮选择一个文件夹即可， 之后这个文件夹里的内容就能在左侧看到。

AI 助手点了没反应 / 报错

AI 助手需要你自己提供 OpenAI 兼容的接口地址、API Key 与模型名（设置 → AI 服务）。 应用不内置任何密钥，也不会代替你请求任何第三方服务。填好后可以用「测试连接」确认。

会话录制存在哪？怎么看？

录制文件在 ~/Library/Application Support/Sennit/recordings/， 格式是 asciicast v2（纯文本，可以直接用文本编辑器看，也能用 asciinema 播放）。 应用内的「会话记录」面板可以直接回放、改名与删除。

怎么备份？换机器怎么迁移？

设置 → 备份与还原 → 导出。两种模式：不含秘密的明文 JSON（适合审计留档）， 或带口令密封的整份备份（含凭据，换机器时需要同一个口令）。 在另一台机器上用「还原」导入即可；冲突的条目按 id 判重，默认跳过。

为什么 App Store 版没有内嵌浏览器？

那部分需要按资产单独走代理，而系统提供的浏览器组件要到 macOS 14 才支持按视图设置代理； 直接降级成「全应用一条代理」会让界面显示走了隧道、实际没走 —— 那种「看起来生效、其实没有」 是运维工具里最不能有的东西。所以这一版不含它。

为什么 App Store 版没有本地终端？

不是取舍，而是系统限制：App Store 版运行在 App Sandbox 里，系统只允许应用读写伪终端的从设备， 不允许对它下发终端控制指令。结果是 shell 无法关闭按键回显、也无法把自己设为前台进程组 —— 你会看到「输入第一个字母重复一次、方向键打印成 ^[[A、必须回车才执行」。这在沙箱内无法修复， 所以这一版直接不提供。SSH 终端不受影响。

串口列表是空的

先确认 USB 转串口驱动已安装、设备已插好，然后点串口下拉旁边的刷新按钮。 列表为空时仍可以手工输入设备路径（如 /dev/cu.usbserial-1420）。

远程转发（-R）显示运行中，但外面连不进来

服务端的 sshd 默认只允许远程转发绑定到回环地址，需要服务端开启 GatewayPorts 才能从外部访问。这是服务端配置，不在应用控制范围内。

Features limited by App Sandbox

The App Store build runs inside App Sandbox. The following capabilities are not provided by the system itself, so this build does not include them:

Feature App Store build Outside the sandbox
SSH / Telnet / SFTP / port forwarding / batch / recording / AI / notes Available Available
Embedded browser (Web-type hosts) Not included. Double-clicking such a host explains this; the host itself is never deleted Available
Import from ~/.ssh, list local keys Not included (sandbox cannot read your home folder) Available
SFTP local pane Only folders you have picked in a dialog Any folder
Local terminal Not included. App Sandbox does not let an app set line editing or foreground process groups on a pseudoterminal, so keys repeat and arrow keys stop working — a system limitation that cannot be fixed inside the sandbox Full machine access

Both builds share the same vault format: hosts created outside the sandbox are visible in the App Store build (the few unavailable features simply cannot be used there).

Frequently asked questions

I forgot my master password. Can you recover it?

No. The vault is encrypted with AES-256-GCM and the key is derived from your master password. We store neither the password nor an escrowed key, and there is no backdoor. The only way back is a backup you exported earlier (which also needs its own passphrase, if you set one).

"Host key unknown" or "host key has changed"

The first time you connect to a machine, the app asks you to confirm its host key — check the fingerprint and accept. If a machine you have connected to before suddenly reports a changed key, it may have been reinstalled — or someone may be intercepting the connection. The app cannot tell those apart, so the decision is yours: verify the fingerprint through another channel before continuing.

The SFTP local pane asks me to pick a folder

The App Store build is sandboxed and can only reach folders you have explicitly granted. Click the button in that message and pick a folder; its contents then appear in the left pane.

The AI assistant does nothing / returns an error

The assistant needs an OpenAI-compatible endpoint, API key and model name that you supply (Settings → AI service). The app ships with no keys and never calls a third-party service on your behalf. Use "Test connection" after filling them in.

Where are session recordings?

In ~/Library/Application Support/Sennit/recordings/, in asciicast v2 format (plain text — readable in any editor, playable with asciinema). The in-app Recordings panel can replay, rename and delete them.

How do I back up or migrate to another Mac?

Settings → Backup & Restore → Export. Two modes: a plain JSON without secrets (handy for audits), or a passphrase-sealed full backup (includes credentials; the same passphrase is needed on the other machine). Import it there with Restore. Duplicate entries are matched by id and skipped by default.

Why is there no embedded browser in the App Store build?

That feature needs a per-host proxy, and the system web view only supports per-view proxies from macOS 14. Falling back to a single app-wide proxy would mean the UI shows traffic going through your tunnel while it actually does not — the one failure mode an operations tool must never have. So this build leaves it out.

Why is there no local terminal in the App Store build?

This is a system limitation, not a design choice: the App Store build runs inside App Sandbox, which lets the app read and write the pseudoterminal slave device but not send terminal control requests to it. Without those, a shell cannot turn off key echo or make itself the foreground process group — you get “the first letter repeated, arrow keys printed as ^[[A, and Enter required to run anything”. That cannot be fixed inside the sandbox, so this build does not offer it. SSH sessions are unaffected.

The serial port list is empty

Make sure the USB-to-serial driver is installed and the device is plugged in, then hit refresh next to the port dropdown. You can always type a device path manually (e.g. /dev/cu.usbserial-1420).

Remote forwarding (-R) says it is running, but nothing can connect

sshd only allows remote forwards to bind to the loopback interface by default; the server needs GatewayPorts enabled for external access. That is a server-side setting, outside the app's control.
